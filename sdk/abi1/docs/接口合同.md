# ABI1 公共 BLE 服务合同

公共头 `include/ns_ble.h`；示例 `examples/ble_service.c`。本接口是新的离线开发候选，hardware_tested=false；不能继承 NS6 固定广播标记的历史实机 PASS。

## 接入与生命周期

应用在匹配固件的常驻宿主、已验证 UI 上下文调用 `ns1_ble_open(&radio)` 一次，radio 初值 NULL。它捕获 UI owner 并分配驻留服务，后续复用这个指针。Band11 仍要求 UI48；这不是可以从任意线程或任意第三方加载器调用的系统服务。宿主必须独占本 SDK 无线角色，不能同时启动 NS6 演示后端、另一服务或 ABI3。接口不提供跨模块仲裁。

服务包含 controller、回调所需管理存储和 RX 队列；没有应用回调、user 指针或页面引用。页面之间切换不调用 stop/exit，仍由应用 owner 的 UI timer 定期 poll，页面读取应用自己的状态副本。页面对象可以销毁；服务、代码、宿主、timer 必须在原有驻留合同内存活。页面卸载与模块卸载不是同一件事。

`ns1_ble_start(radio, roles, ad, length)` 排队启动意图，poll 才创建 worker。roles 是 NS_SCAN、NS_ADV 或两者。`ns1_ble_stop` 撤销待发意图并协作停止所有自有角色，保持 poll；quiet 后可再次 start。`ns1_ble_exit` 永久拒绝本服务的新启动，并取消待发帧。它幂等，但不销毁驻留服务。退出期间宿主仍须驱动 UI，不能先删除清理 timer、撤走代码或强制释放服务。

清理继续使用原后端的角色终结、内部 barrier、真实线程退出、join，以及后续 UI/queue/timer 证明。任何原有错误进入 HELD；新服务在观测到停止后累计 10 秒 polled clock 仍不 quiet，也进入 HELD，不再重启或释放。没有 UI poll 时此期限不能运行；共享同步 RPC 不能硬取消。HELD 不代表线程已停，服务和代码继续驻留，不能改写未知引用来“恢复”。正常退出只回收会话 owner，管理服务仍留至重启。

## 广播与背压

AD 是完整 legacy advertising data，含 AD length/type 字节，1..31 字节；允许零填充尾部，拒绝截断 AD 元素、非零填充尾部、NULL、0 或大于 31 的广播。SDK不添加标记、设备名或业务格式。scan-only 使用 NULL,0。按已有固件配方广播，不开放间隔、发射功率、扩展广播或连接参数。Band11/S4 各自使用原来的编码与适配，不推定无线行为相同。

`ns1_ble_change` 仅在 ACTIVE、包含 NS_ADV 且没有待发帧/停止请求时接受；成功前复制输入。1 槽待发帧，满返回 BUSY，调用方保留新内容稍后重试，不覆盖旧帧。接受后停止扫描和广播，完整回收旧会话后创建新会话；这是有间隙的换帧，不能承诺持续无缝扫描。两次启动至少间隔 1000ms，实际速度还受停止与清理耗时影响；OK 只表示接受意图，不保证该帧已在空中出现或被收到。若立即换帧，旧帧可能尚未发送，应用应按需求保留足够驻留时间。

`ns1_ble_poll(radio, now_ms)` 由应用提供单调 uint32 毫秒，允许自然回绕，相邻调用间隔须小于 2^31ms，逆行拒绝且不推进状态。建议沿用宿主 100ms UI tick；原 worker 的 heartbeat 守护继续有效。禁止通过伪造时钟绕开发送节流。没有无间隙热更新 RPC、无限发送队列、分片、ACK、可靠送达或系统挂起保证。

## 扫描数据与状态

固件回调先验证上下文及 generation，再复制最多 31 字节有效数据到驻留 RX8 队列；单一已验证 callback producer 和 UI consumer 用 acquire/release 发布槽位。应用通过 `ns1_ble_receive` 得到完整值副本，可自由保存，不持有固件指针。清理不依赖应用是否读空 RX。跨会话积压报告带原 generation，应用自行过滤；不静默清空旧报告。

满队列丢弃新报告并增加 dropped_rx（uint32 计数），不覆盖未读数据；空队列 BUSY。扫描报告允许 0 字节数据，保留原始 AD，不解析业务、不去重、不提供地址/RSSI。接收内容不可信，应用必须验证格式；没有地址意味着本接口本身不提供设备身份或可直接连接的 peer 句柄。无效固件报告不入队。

所有接口在捕获的 UI 上串行调用；没有应用 observer 的重入问题。observe 返回 state/generation/error/pending/queued_rx/dropped_rx/quiet/exiting 的值副本。error 沿用原后端诊断码，非稳定跨固件错误 ABI；HELD 状态本身也是明确失败反馈，清理超时可以 error=0。NS_OK 为操作接受/有效推进；NS_BUSY 为状态、队列或节流暂未允许；NS_INVALID 为参数、上下文、最终退出后调用或 HELD 拒绝；NS_EXHAUSTED 为分配/代数耗尽。poll OK 不等于 ACTIVE 或 quiet，必须 observe。

## 验证边界

`tools/verify_contract_arm.py --ble` 执行公共服务、真实 session/controller、收包队列及两设备 packet 编解码；固件调度、worker 和清理证据由模型提供。既有 ARM/UI/ROM 模型继续验证后端。新接口与动态帧换代仍需两台设备分别验收，不能用模型替代。
