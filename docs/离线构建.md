# 离线构建与验证

所有命令从仓库根目录执行。构建只在新建的 work/ 副本中进行，候选写到 outputs/；不会联网、操作 GUI、蓝牙、安装设备包或重启设备。依赖安装是单独的准备步骤。路径通过结构化参数传递，支持空格。

## 外部依赖

参考环境为 Windows x64 / Python 3.12.10。公共 CI 配置覆盖 Windows 和 Linux 的无固件检查；完整固件流水线目前仅在本机 Windows 验证，不承诺其他平台完整构建已验。

| 依赖 | 固定版本或输入 |
|---|---|
| Zig | 0.13.0；从 https://ziglang.org/download/ 取得，版本不符会拒绝构建 |
| Python 包 | requirements-build.txt：pyelftools 0.33、Unicorn 2.1.4 |
| Lua | 标准 Lua 5.4 命令行解释器；从 https://www.lua.org/ftp/ 取得，本次另用标准 5.4.0 验证；不是设备命令工具 |
| Band AP | 4.100.179；SHA256 307adabe0ff61c77be73d045a8260e279cddd131c7a535a2678eb34199278a2b |
| S4 AP | 3.111.032；SHA256 86a8580db2f603101de017607b509b1968c10122c62c33323684bc13a54b9158 |

仓库不提供固件、下载地址或授权状态。完整流水线目前需要两份 AP，尚不支持按单设备选择构建。

```powershell
python -m pip install --target work/python-deps -r requirements-build.txt
Copy-Item config/local.example.json config/local.json
```

编辑 config/local.json：zig、lua 指向真实可执行文件；python_deps 指向刚安装的目录；band_ap 和 s4_ap 指向自行准备的精确 AP。相对路径以仓库根目录为基准，不以配置文件位置为基准。Linux 使用相应无 .exe 的可执行文件路径。所有配置键都必须显式提供，不搜索旧工作区。

## 三种检查范围

```powershell
# 无需固件、编译器和第三方 Python 包：白名单/文本检查、Python/JSON 语法、验收解析器、来源清单及导出边界测试
python tools/check_public.py

# 额外执行无固件的 ARM 生命周期模型（13 场景；调度/后端为模型）
python tools/check_public.py --toolchain local-assets/zig --python-deps work/python-deps

# 完整公开构建：需要上述全部外部依赖，但不需要 imports/
python tools/integrate.py --mode public --config config/local.json
```

公开构建依次执行 ABI1 库/组件/示例、NS6 宿主、ARM/UI/ROM loader/重定位模型、ABI3 库与宿主、ROM/资源/SDK 模型、示例链接、验收文本解析、Lua fixture 和双 ABI 冲突检查。不能把离线模型描述成无线硬件或设备验收。

公开来源审计只比较当前文件和记录的来源哈希，明确 frozen_origins_verified=false、all_origin_hashes_match=null。公开模式使用 config/public-baselines.json 的哈希作比较；不读取历史库，不进行旧 archive 符号逐项比较。不同产物的哈希会如实记录，不用历史设备 PASS 为新产物背书。

每次运行的日志和输入哈希保存在 work/integration-*/run.json；意外失败停止并保留 complete=false。该本机报告包含绝对路径，不能直接上传。只有成功流水线导出 outputs/ 下的本地 SDK 候选，均 hardware_tested=false；不生成 face。

## 可复现性与历史回归

用相同配置和依赖重复公开构建，可对比前一次成功报告：

```powershell
python tools/integrate.py --mode public --config config/local.json --compare "work/integration-前一次目录/run.json"
```

比较要求源码、编排、工具、Python、依赖和配置相同，逐字节核对候选产物；不要求带绝对路径和时间的日志相同。

维护者保有完整私有迁移档案时，历史模式额外核验冻结来源、旧库/宿主和 archive 符号定义：

```powershell
python tools/integrate.py --mode historical --config config/historical.example.json
python tools/verify_migration.py
```

historical.example.json、config/baselines.json、verify_migration.py 和原始迁移报告属于本地维护资料，不随公开仓库分发。缺少历史资料时历史模式必须失败，不能静默降级成公开模式。

## 源码导出

```powershell
python tools/prepare_public.py --check
python tools/prepare_public.py --release
```

仅导出 config/public-files.json 逐文件列出的 UTF-8 文件到新的 outputs/public-source-*，附 files.json 哈希清单。禁止私有目录、二进制和越界/符号链接，检测若干常见凭据及本机路径格式；检查通过不替代人工审核。它不会初始化 Git、提交或上传。
