# 开发与交接流程

## 开始任务

读 AGENTS.md、README.md、当前工程结构与能力边界，确定涉及 ABI、精确机型/固件和是否需要真实设备。公开检出缺少 local-private/ 与 imports/ 是正常状态，不要要求先取得历史档案才能修改公开源码。维护者本地还应阅读 local-private/README.md 和当前状态文件。

修改 sdk/ 中的活跃实现。需要原始证据时按来源索引读取指定记录；归档脚本和旧提示只作历史材料。当前任务以用户要求为准，路线图和旧状态的 next_task 不自动授权执行。

## 新增与移动文件

1. 新增提取在 migration/active-sources.json 记录冻结来源及原哈希；移动已登记文件时更新 active，保留 source/source_sha256 和 previous_active。
2. 审核许可与公开内容后，把新增公开文件加入 config/public-files.json，移动文件同步修改清单路径。禁止把私有资产加入清单。
3. 执行 `python tools/sync_public.py` 生成 .gitignore。它保持默认拒绝、逐文件允许，不自动发现或批准新文件。
4. 执行 `python tools/check_public.py`；按修改范围增加 ARM 模型或完整离线构建。提交前核对 Git 文件集与公开清单一致，并审核 diff。

## 结果与产物

构建和检查在各自的新运行目录保存 run.json，不覆盖旧记录。候选输出带 hardware_tested=false。公开源码导出在 outputs/source/，不会自动发布；outputs/releases/ 需要明确选择交付及相应验证说明。不要把原始 run.json 直接上传，其中可能包含本机绝对路径。

每次交接说明具体改动、检查结果、未完成项和相关 commit。本地维护状态在 local-private/project/PROJECT_STATE.json 更新；公开能力边界发生变化时同步支持文档。保留历史验收对应的库/设备包哈希，不将新构建覆盖为旧 PASS。

## 本地资料保留

local-private/archive/ 保留旧工作过程，outputs/archive/ 保留旧产物。二者都不是可随意清空的缓存。work/ 的运行也可能是尚未归档的唯一证据，清理前先确认引用与保留要求。当前工具不提供自动删除或设备安装操作。
