# 独立应用接入与 ABI 协作评估

本轮只完善通用 SDK，没有聊天协议、业务 ACK、联系人、记录库、加密或 UI。新增能力为离线候选，hardware_tested=false。历史事实以支持文档的冻结验收摘要为准。

## 推荐接入

先选一条 ABI、精确固件和对应常驻宿主。ABI1 使用 `ns_ble.h` 的公共服务，合同与示例分别在 sdk/abi1/docs/接口合同.md、sdk/abi1/examples/ble_service.c；支持扫描原始 AD 和有间隙的自定义短帧换代。原 ns_session/ns_controller/nss_flow 保留，nss_flow 仍是页面可见性驱动，不能把每页的 show/hide 直接当成应用通信生命周期。

ABI3 使用 `ns_link_v3.h`，应用 owner 复用一个 runtime，创建 link，页面只观察应用状态。内部页面切换不 disconnect/close；真正退出 close，继续 UI 调度，最后在 observer/dispatcher 之外 destroy。保留资源时不能撤走 runtime 代码。fixed_channel 示例补充显式 stop，并将默认行为简化为断开后 close；应用 owner 按需显式重连并检查返回值。原实现可以从 DISCONNECTED observer 接受重连意图，至少 500ms backoff 由 worker 内部执行；无需把这段等待阻塞在 UI 上。

这仍不是任意第三方 APP 加载器都可直接使用的系统 SDK：加载、UI owner、驻留宿主和精确适配是前提。可以开始前台原型开发；尚不适合作为已验证的全天在线、穿戴双端可靠通信产品基线。动态广播是发现/短数据实验路线，未解决双端 GATT 和后台可用性。

## ABI1 与 ABI3

现有重复定义包括 ns_ble_* packet、nsp_* port、nsr_* radio 等私有符号；公共 ns3_* 命名不能解决私有合同冲突。两库还有不同 owner/token/退休模型，隐藏符号或改名只解决链接表象，不构成资源仲裁。继续分别构建，不传递 controller、token、runtime 或私有对象。

最低风险的当前方案是让应用选择一种传输：ABI1 广播收发，或 ABI3 固定 GATT Client。ABI3 本身已为服务发现执行扫描，不需要为连接 Windows peripheral 同时引入 ABI1。穿戴端广播发现加 GATT Server 则不是已有完整能力。

后续优先评估在 ABI3 自己的 runtime 下增设一个通用发现接口，借用其已有扫描与调度，而不是整库并入 ABI1。第一阶段只交付带 generation 的值副本发现数据，与 GATT 连接扫描串行；必须新增取消、退出、背压和错误回收模型。需要发广播时仍要在 ABI3 自有 token/退休模型中适配原语，不能移植 ABI1 owner 内存结构。

若确需双模块协作，可考虑常驻 broker：版本化命令和复制数据，只有 broker 借用 BT client 并拥有自有角色，应用侧不链接另一 ABI。此路线需要加载、调度、权限、跨模块生命周期与回调退出证明，当前未实现。没有评估过跨 ABI IPC，不能把分开加载称为已安全协作。

真正统一运行时之前，必须先版本化私有 backend/link 合同、列出每种角色的唯一 owner、明确 client 借用边界和冲突返回，再新增仲裁测试。共享系统 BT client 不能关闭/删除，不能复用未知 scanner/advertiser、抢占其他连接或用忽略重复符号链接。两种方案均需独立硬件验收，本轮不更改两条已验传输核心的资源模型。

## GATT 支持与后续验证

Band11 M2617B1/4.100.179 当前为 central/GATT Client，匹配指定 128-bit service/channel UUID，固定流程扫描、连接、发现、READ/WRITE/NOTIFY、自动初次读取。发送 1..20 字节、TX4、RX8；不是任意服务/特征浏览器。前台 SOLO Windows peripheral 历史通过，正常显式重连 8 轮；ATT 写响应和 notify 不证明业务送达。ABI3 公共接口已有复制、错误、背压、UI observer、close/destroy，诊断 snapshot 仍是实验接口。

GATT Server/Peripheral 有实现路线但没有当前 SDK 的已验接口。sdk/abi3/reference/upstream 的 bt_gatts、socket 消息及 gatt_server 工具仅提供上游语义参考；必须针对 Band11 精确 AP 核实入口、结构、服务注册、advertiser、属性存储、连接/订阅回调和注销/退休合同，证明共享 BT client 可安全支持。不能照搬上游地址或用 S4 的 PC API 实验推定 Band11 可用。

穿戴之间走 GATT 至少缺少：一个穿戴端可用的 peripheral/server、匹配服务与特征、可发现且可连接的广播、连接身份/地址交付、双端角色与退场所有权验收，以及断线/超长/满队列/取消/共存条件下的双端测试。现有 ABI1 RX 只有 AD 字节，不能直接变成 ABI3 peer 对象。

error51 已知证据是同包手机连接共存 3/4、51，而手机断开 SOLO 4/4；旧短时 UI 观察不能覆盖此失败。51 表示非预期断线，尚不能归因手机、同步、资源竞争或射频。后续真机计划需另行授权：固定包/库/AP/PC 服务和测试次数，分别对比手机断开、连接空闲、同步三组；记录有时间戳的双方连接/断开原因、扫描/发现/订阅阶段、RPC 和 token/queue/worker 清理快照。每轮先正常 close/destroy，HELD 停止该轮，不复用未知 owner；不自动重启/清空系统对象。先复现和归因，再评估有限重试。新 owner 不能保证从 51 恢复。

自然熄屏、系统挂起/唤醒、功耗、长期在线、模块卸载和新广播换帧均待独立实机测试。本轮未安装、刷机、重启或进行其他设备操作。
