# 工程整合（2026-11-16）

本文记录本地历史整合。公开仓库不包含 SOURCE_MAP.json、imports/ 或 docs/validation/ 下的本机原始报告；历史入口名用于关联 migration/active-sources.json 的来源记录，公开结果摘要见 docs/验收摘要.md。当前默认公开构建和可选本地历史回归的差别见 docs/离线构建.md。

活跃主工程是 `sdk/`。ABI1 与 ABI3 是同一工程中的两条隔离组件线，配套构建图不同；没有创建新的共同设备 ABI。生产 C、汇编、加载模板与关键公开头优先逐字节提取，构建组织和离线测试运行器允许调整。逐文件冻结来源在 `migration/active-sources.json`；`tools/audit_sources.py` 校验来源哈希并区分 byte_preserved、adapted、new，允许删除的重复/历史辅助文件以 retired 明确登记。

| 职责 | ABI1 | ABI3 |
|---|---|---|
| 公共接口 | `include/ns_session.h`、`ns_controller.h`、`ns_sdk_flow.h` | `public/ns_link_v3.h`，单一权威副本 |
| 生命周期/通用核心 | `src/ns_session.c`、`ns_controller.c`、`ns_sdk_flow.c` | `src/ns3_runtime.c`；内部生命周期由配套 port 驱动 |
| BLE/GATT 后端 | `src/ns_sdk_ble_backend.c`、`ns_sdk_page.c`、`ns_ble_packet.c` | `src/g1_runtime.c`、`ns_ble_packet.c`、`platform/gatt_resource.c` |
| 固件适配/profile | `platform/port.c`、`radio_port.c`、`reference/*-abi-profile.json` | 对应 Band11 port/radio、`reference/band11-abi-profile.json` |
| 宿主/加载器 | `src/ns_default_shell.c`、`platform/band_default*`、`s4_default*`、`device/` | `src/g2_consumer.c`、`device/`、`reference/band_loader.lua.in` |
| 公开示例 | `examples/lifecycle.c`，只用三个公共头；`templates/` 是另外的旧平台组件层 | `examples/fixed_channel.c`，只用公共头 |
| 测试器 | `tests/`、内部 `tools/` | `tests/`、内部 `tools/`；Windows 真机对端仍索引冻结资料 |

上表路径相对于各 ABI 目录。ABI1 的 `include/` 还保留平台适配器必需的旧结构头；本地候选分别导出公共 `include/` 与 `platform-adapter-include/`，不能把后者当成跨固件稳定 ABI。私有地址、RPC/token/线程/释放不进入 ABI3 公共头。两端 profile 的历史 B36 字段是研究合同，当前 NS6 管理层仍 HELD；profile 不能替代当前支持表。

| 来源入口（SOURCE_MAP） | 提取/保留方式 |
|---|---|
| ns6_engineering | 选择 ABI1 核心、零额外保留 NS6 宿主、构建配方、默认模型、Lua 和许可 |
| abi1_sdk | 作为基础研究入口保留，不重复创建第二条活跃 ABI1 树 |
| gatt_source | 选择 G4R2/ABI3 库、资源管理、消费者、ROM/ARM 模型、接口合同和上游语义参考 |
| gatt_release | 公开头/示例来源，静态库作为只读哈希与定义比较输入 |
| local_research_inputs | 仅提取 S4 ROM loader 模型的必要辅助源码；固件/依赖另作配置输入 |
| gatt_acceptance、band_stage_original_records | 留在 imports，沿 SOURCE_MAP 访问，不改原文/manifest |
| S4 lab/phase2、早期 native 研究、入口刷新调查 | 保留冻结索引，未并入 Band 产品 API；需要时按证据选择 |

链接检查实际发现 37 个重复定义，包括 `ns_ble_*`、`nsp_*`、`nsr_*`、`memcpy/memset` 和 AEABI 辅助函数。`--whole-archive` 双库诊断链接因 duplicate symbol 被拒绝；这不是任意应用链接的穷尽性证明，但足以禁止宣称两库可直接组合。具体名称、每库定义、stderr 和哈希在运行报告与日志中。不能用链接顺序或允许重复定义来绕过：同名私有适配器可能具有不同语义。公开的 `ns3_*` 与 ABI1 对象也不能互传。

本轮没有给生产代码改名、重排结构或新增设备能力。重建三份库、五个宿主/加载产物及四份公共头逐项与冻结输入比较。最终字节与可复现性结果以 `docs/validation/integration.json` 为准；新编译的库、示例链接物和模型均是本轮候选，不继承新的设备 PASS。候选输出与历史 face 无新安装关联，也没有设备回读。

后续按以下顺序推进：先给需要组合的私有适配层设计版本化/命名空间方案及链接合同，再处理有界异常恢复与手机共存 error51；其后单独设计后台/熄屏/唤醒、长期在线和功耗验收。手环首次入口列表刷新仍是独立缺陷。真正模块卸载必须重新收敛 owner、callback、queue、timer 和线程证明，不能从 session quiet 推出。NFC 独立做可行性任务。应用层协议由 SDK 使用者自行实现，不从 S4 固定向量实验推导 Band 安全能力。
